# Project

**Laqi** (GitHub `csdev19/laqi`, public; npm package `laqi`): a controllable local mock API server for frontend development.

## Purpose

`npx laqi` serves mocks from `./laqi/` or `./laqi.json`. A web panel at `/__laqi` lets you flip responses, errors, latency and scenarios. Laqi also has an MCP server for coding agents, a public-URL sharing mode, and type/data generation. v2 has been live on npm since 2026-09-02.

## Stack

- TypeScript, Bun 1.3.4 workspaces + catalog, Turborepo, tsdown
- Hono (mock server), Zod (schemas), React + Vite (panel), MCP SDK
- Vitest at the repo root, oxlint + oxfmt
- Astro Starlight for the internal docs, Astro for the public site (laqi.dev)
- release-please with npm publishing via GitHub Actions

## Structure

- `packages/schema`: Zod schemas. `packages/core`: loading, route table, resolution and the state store.
- `packages/server` is the Hono app. `packages/editor` is the panel. `packages/mcp` is the MCP server.
- `packages/generate`, `packages/tui`, `packages/tokens` and `packages/config` hold generation, TUI, design tokens and shared config.
- `apps/cli`: the published `laqi` binary. Its `README.md` is the one npm shows.
- `apps/documentation`: internal docs (ADRs in `decisions/`, briefings in `product/`). It is never deployed.
- `apps/site`: the public site. `examples/todo-app` is a TanStack Start demo.
- `.claude/briefings.md`: binding for the `generate-briefings` skill

## Commands

- `bun install` / `bun dev` runs the CLI against `examples/todo-app/laqi`, the panel on :8000/\_\_laqi and the example on :3000
- `bun run dev:hmr --filter=@laqi/editor` gives panel HMR on :5173 (the CLI must already be running)
- `bun run build` builds the panel and bundles it into the CLI → `node apps/cli/dist/index.mjs`
- `bun run test` / `bun run check-types` / `bun run check` (lint + format)
- **Before any PR: `bun run verify`.** It mirrors the CI `validate.yml` checks: check:ci, build, check-types, check-types:scripts, test.

## Agent Rules

- PR titles and commits must be Conventional Commits. They drive release-please versioning.
- `docs:` is hidden in the release config and cuts no version. A change that must reach npm needs `fix:` or `feat:`.
- Merging the rolling release PR **is** releasing. Never merge it, and never publish from a laptop.
- `apps/cli/README.md` is the npm page. The root `README.md` is for contributors. Keep them separate.
- Record architectural decisions as ADRs in `apps/documentation/src/content/docs/decisions/`.
- Write the code and docs in English.
