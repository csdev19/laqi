# laqi v2 — Plan 3: MCP server

**Status:** executed. Log of what was built.

**Spec:** [ADR-0006](/decisions/0006-mcp-server/),
[the three writers](/concepts/three-writers/).

## What it delivers

`packages/mcp` and the `laqi mcp` command, which serves it over stdio.

## The architecture decision: files, not HTTP

The MCP server **does not talk to a running laqi**. It operates directly on
the project's files using `@laqi/core`.

This works because the mock server reads state on every request and the
watcher picks up file changes. It's worth it because an agent can build
mocks with laqi turned off, and they work the moment you start it — no
coordinating two processes, and no agent having to guess which port the
server is on.

Every call reloads from disk: the panel, the web editor, and the developer's
own hands write the same files, and a cache here would go stale instantly.

## Tools

| Tool              | What it does                                                             |
| ----------------- | ------------------------------------------------------------------------ |
| `list_endpoints`  | Every endpoint, its responses, and which one is live and by which layer  |
| `get_state`       | Active scenario, overrides, and only the endpoints outside their default |
| `set_response`    | Sets an endpoint's live response; `null` clears the override             |
| `set_scenario`    | Activates a scenario; `null` deactivates it                              |
| `reset_state`     | Clears overrides and scenario                                            |
| `create_endpoint` | Creates an endpoint and writes it to the file                            |
| `update_endpoint` | Replaces the full definition                                             |
| `delete_endpoint` | Deletes it, and clears any override pointing at it                       |
| `import_openapi`  | Generates mocks from an OpenAPI 3.x document                             |

The ADR listed seven; `delete_endpoint` (the H8 fix Plan 2a had already made
over HTTP) and `reset_state` were added.

### The instructions teach the layer model

The server sends instructions explaining what an endpoint id is and in what
order the layers win, with the rule that an override beats the scenario and
that returning to the default means using `response: null` rather than
naming it. Without that the agent guesses, and guesses wrong: writing an
override identical to the default leaves the endpoint marked "changed"
forever.

### Errors come back as `isError`, not as an exception

An agent has to be able to read the reason and correct it. `set_response`
with a nonexistent response returns which ones do exist; an unknown endpoint
returns the list of known ids.

## `import_openapi`

Converts an OpenAPI 3.x document into endpoints, generating example bodies
from the schemas.

- **JSON only.** Bringing in a YAML parser would be a large dependency for
  something the calling agent can convert itself.
- **Never throws.** Whatever it can't convert comes out in `skipped` with the
  reason. A hundred-route spec with two odd ones is worth more imported at
  98% than rejected outright.
- **Overwrites nothing by default.** An endpoint that already exists is
  reported as skipped; `overwrite: true` must be requested explicitly.
- Response names come from the status (`200` → `ok`, `404` → `not-found`,
  `500` → `error`), not the number: an agent asks for `boom`, not
  `status-500`.
- The default is the lowest 2xx — the happy path.
- Handles circular `$ref`s (common in real-world specs), merges `allOf`,
  respects `example` / `default` / `enum` / `format`, and skips the range
  keys (`2XX`, `default`) that OpenAPI allows but that aren't a concrete
  status.

## Three validation holes that got closed

The ADR warned: "an agent with these tools can write project files. It must
be strictly confined to the mocks directory — never outside it." Building it
surfaced three real gaps:

1. **`writer.ts` didn't contain the writes.** `join(root, file)` lets
   `'../x.json'` escape the project. Now every writer goes through a guard
   that resolves the path and refuses if the result falls outside the root.
   **It wasn't theoretical:** the first run of those tests, before the guard
   existed, left an `escaped.json` in the machine's shared tmpdir.
2. **`Project.createEndpoint` wrote before validating.** An agent creating
   `/__laqi/...` got back `ok` and a mocks file that then failed to load. It
   now validates with the same `parseEndpointKey` the loader uses, before
   touching disk.
3. **`parseEndpointKey` accepted `..` segments.** A URL gets normalized
   before routing, so that path can never actually be reached: it was a dead
   endpoint written silently into the user's file. It's now an explicit
   error.

All three fixes live in `packages/core` and `packages/schema`, so they also
benefit the control plane and the editor.

## Verification

- **62 package tests**, **14 of them driving the real server over real
  stdio** with the MCP SDK client — `bun apps/cli mcp` is spawned in a
  temporary directory and the real protocol is spoken.
- 358 tests total across the repo, `check-types` and `lint` clean.

## Out of scope

- **YAML** in `import_openapi` (see above).
- **Templating** (`{{uuid}}`) still has no plan assigned.
- The MCP server **does not expose the live request log**: it's a stream,
  and MCP tools are request/response. A buffered `recent_requests` would be
  the design, but it requires talking to the server process — exactly the
  coupling this plan deliberately avoids.
