# laqi v2 — Plan 4: Public URL

**Status:** executed. Log of what was built.

**Spec:** [ADR-0007](/decisions/0007-public-url/), finding H1 from the
[design review](/design/review-vs-decisions/).

## The problem it solves

On React Native you can't use `localhost` as a backend. The physical device
doesn't resolve your machine's `localhost`, Expo Go over mobile data can't
see your local network, and a teammate on another network can't reach your
mock.

`laqi --share` opens a public `*.trycloudflare.com` URL that points at your
mocks.

## H1 closed by architecture, not by a rule

Finding H1 was blocking: if the tunnel passes everything through, anyone with
the URL **rewrites your mock files on your disk**.

The resolution isn't to protect the control plane behind the tunnel. It's
that **it isn't there**:

```
local port  (127.0.0.1:8000)   mocks + control plane + panel
public port (127.0.0.1:8001)   mocks ONLY           ← the tunnel points here
```

`--share` starts a **second listener** that mounts only the mocks surface.
The control plane isn't protected on that port: it doesn't exist. The
explicit 404 for `/__laqi/*` inside the public app is defense in depth for
the day someone mounts it there by mistake — and it responds with **404, not
403**, so as not to confirm the control plane exists.

Both listeners bind to loopback: cloudflared runs on your machine and
connects locally. Binding the public one to `0.0.0.0` would expose it to the
LAN as well as the tunnel, without anyone having asked for that.

## The ADR's five measures

1. **Mandatory token.** The CLI generates one, prints it, and every request
   without `Authorization: Bearer <token>` gets a 401. The comparison is
   constant-time: a plain `===` leaks how many leading characters you got
   right, and these URLs get scanned by bots. Disabling it requires
   `--public`, which prints a warning.
2. **Restricted CORS.** Never `*`. Only the origins from
   `laqi.config.json`. With the default config no browser origin is allowed
   at all — which is the safe state. `curl` and React Native don't send
   `Origin`, so they keep working.
3. **The panel and MCP aren't exposed.** See above.
4. **Rate limiting**, with a per-caller ceiling and a global ceiling. The
   global one is what actually protects: `CF-Connecting-IP` is set by
   cloudflared, but whoever hits the port directly could fabricate and rotate
   it. Rotating it dodges its own bucket, not the global one. It runs
   **before** auth, so a flood of bad tokens is cheap.
5. **A startup notice** stating what got exposed, with which token, and a
   ready-to-copy `curl` command.

Plus what H1 additionally called for: **the panel's magenta band says it in
words** — `mocks only — the panel and the control plane are not exposed`. An
invisible guarantee becomes something the user reads.

## `TunnelProvider`

The sharing layer is a pluggable interface from day one, as the ADR asks.
`CloudflaredProvider` is phase 1; a self-hosted relay on Workers plugs into
the same interface without rewriting anything.

It detects whether `cloudflared` is installed **before** opening any port —
if it fails after the startup banner, it would look like something was left
half-done — and if it isn't installed, it says how to install it on each
platform.

## Two real bugs the tests found

1. **`Access-Control-Allow-Origin: *` leaked through the tunnel.**
   `createMockApp` mounts its own `cors()`, which runs after the public app's
   and overwrote the restricted header — exactly what the ADR forbids. Fix:
   `createPublicApp` receives the mock app's **runtime**, not an already-built
   app, and assembles the mock app with the correct origins. The bug becomes
   unrepresentable.
2. **Aborting the tunnel's startup hung the CLI.** The process got killed
   without resolving the promise, and since the abort marked it `settled`,
   the subsequent `exit` couldn't reject it either.

## Verification

- **401 tests**, `check-types` and `lint` clean.
- Live verification against a running server, with a replacement
  `cloudflared` (no install needed):
  - mocks return 200 with a token, 401 without one;
  - **every control-plane route returns 404 through the tunnel port even with
    a valid token**, while the same routes return 200 on the local port;
  - a write attempt leaves the mocks file byte-for-byte unchanged;
  - 240 requests go through and the next 10 return 429 with `Retry-After`.

## Out of scope

- **The self-hosted relay on Workers** (ADR phase 2): postponed until it's
  known whether anyone uses `--share`, which is what the ADR decided.
- **Turning the tunnel on and off from the panel.** The design's
  `POST /api/share` wasn't implemented: starting a tunnel from a web request
  is a substantially larger attack surface than a CLI flag, and the flag
  already covers the use case.
- **A stable URL across restarts**: an accepted limitation of cloudflared's
  quick tunnels, and it goes away with the self-hosted relay.
