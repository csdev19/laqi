# laqi v2 — Plan 2b: Web editor

**Status:** executed. This document is the log of what was built,
written against the code as it ended up — not a plan yet to be executed.

**Goal:** `packages/editor`, the React + Vite control panel served at
`http://localhost:8000/__laqi` and consuming Plan 2a's contract.

**Spec:** [design](/design/design/), [screens](/design/screens/),
[interactions](/design/interactions/), [state-model](/design/state-model/).

## What was built

### `packages/editor` — the panel

Vite + React 19, no component library and no CSS-in-JS: CSS variables and a
flat stylesheet, as design section 8 asks. `base: '/__laqi/'` in the Vite
config, so assets aren't requested at the root and don't land on the user's
mock server.

The DOM-free layer is separate and has its own tests:

| File           | What it resolves                                                        |
| -------------- | ----------------------------------------------------------------------- |
| `types.ts`     | The control plane's shapes. `LaqiEvent` comes from `@laqi/core/events`  |
| `resolve.ts`   | Which response is live and which layer decided it; the chip-click rule  |
| `search.ts`    | The list filter and the palette's multi-token matching                  |
| `highlight.ts` | JSON tokenizer (~40 lines, as the design asks) and the validity readout |
| `log.ts`       | Log entries, a 200-entry cap, the `X-Laqi-Resolved` text verbatim       |
| `api.ts`       | Typed client; propagates the error message the server already wrote     |

The components follow the design's tree: `Header`, `ErrorBand`,
`ScenarioStrip`, `EndpointList`/`EndpointRow`, `RequestLog`, `EndpointDetail`
(with `JsonEditor`), `CommandPalette`, `CreateEndpointRow`, `FreshProject`.

### Decisions the design didn't pin down

- **The JSON editor is a transparent `<textarea>` on top of a colored
  `<pre>`**, aligned character by character. The design explicitly asks not
  to bring in a whole editor for this surface.
- **The tokenizer round-trips every character.** Whatever it doesn't
  recognize comes out as `plain`, so a half-written file keeps rendering
  instead of breaking the view. A test verifies this against malformed
  input.
- **No remote fonts.** Source Serif 4 and JetBrains Mono are requested by
  name and fall back to system fonts: the panel has to look the same with
  the wifi off.
- **An endpoint's `default` can never be left pointing at a deleted
  response.** Deleting the response that was the default reassigns the
  default to whichever remains first; otherwise the file becomes invalid and
  the endpoint stops being served.

### Two gaps in Plan 2a's contract that had to be closed

Plan 2a left the request event incomplete for what the design needs from the
log. Both were fixed in `packages/server`, with tests:

1. **The no-route handler emitted no event.** The design makes that row the
   noisiest one in the panel — "why isn't my mock answering?" is the most
   common confusion — and it was literally unbuildable. It now emits, with
   `endpointId: null`.
2. **The event carried `endpoint.path`, the route pattern.** A hundred
   requests to `/users/1..100` looked like a hundred identical rows. It now
   carries the requested path.

`resolvedName` and `resolvedLayer` became optional and are absent on a
no-route event: there was nothing to resolve. The panel branches on
`endpointId === null`.

### `@laqi/core/events` as a subpath

The panel needs the `LaqiEvent` type but runs in a browser, and the
`@laqi/core` barrel re-exports `loader` / `state-store` / `writer`, which
import `node:fs`. The type had been redeclared in the editor, where it could
drift from the real one — and it did drift: `check-types` caught it on the
first build. The `@laqi/core/events` subpath exists for exactly this.

It's the first step on the barrel problem noted when Plan 2a closed.
`resolve.ts` is the other obvious subpath candidate once something needs it.

### `apps/cli` serves the panel

`createEditorApp()` mounts **before** the control plane, because the control
plane ends in a catch-all that would swallow `/__laqi` and
`/__laqi/assets/*`. It sits behind the same loopback gate: with
`--host 0.0.0.0` neither one gets mounted.

- `dist/`'s path is resolved via the module resolver, not relative to the
  file, so it keeps working once the CLI is packaged (Plan 5).
- **Path traversal is explicitly rejected.** The guard is load-bearing:
  verified by removing it, and Hono does **not** normalize `..` in the URL —
  `/__laqi/assets/../../<file>` reads outside `dist/` without it.
- Without a build, it responds 503 with a page stating which command to run,
  instead of a silent 404.

## Verification

- **331 tests** total (290 from the repo + the panel's), `check-types` and
  `lint` clean.
- 37 panel tests run the real React tree in jsdom.
- Full round-trip against a real server: the four layers resolve in the
  correct order (`default` → `state` → `scenario` → override beats
  scenario → reset), and create/edit/delete writes the file and is served
  instantly.
- The bundle contains no `node:fs` and no `require(` — verified against the
  build.
- SSE delivers all four events with concrete paths, and the no-route one
  with `endpointId: null`.

## Out of scope

- **The sharing band** (`Share publicly`, the tunnel, the token) belongs to
  Plan 4. The header doesn't draw the button yet: it would promise something
  that doesn't exist.
- **`Open in editor`** (`$EDITOR file:line:col`) needs the CLI to expose a
  route to launch it; no plan assigned.
- **Authoring scenarios** from the panel — [ADR-0008](/decisions/0008-multifile-and-names/)
  already decided it's done by hand or via MCP.
- **`1…9` to flip a response on a focused row** and the row's right-click
  were left undone; the rest of the keyboard map (`⌘K`, `↵`, `⌘↵`, `esc`,
  `/`, `p`) is done.
- **The panel isn't packaged yet** inside the binary: the build has to be
  run once. That's Plan 5.
