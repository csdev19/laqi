# laqi v2 — Plan 2b: Editor web

**Estado:** ejecutado. Este documento es el registro de lo que se construyó,
escrito contra el código que quedó — no un plan por ejecutar.

**Goal:** `packages/editor`, el panel de control React + Vite que se sirve en
`http://localhost:8000/__laqi` y consume el contrato del Plan 2a.

**Spec:** [design](/design/design/), [screens](/design/screens/),
[interactions](/design/interactions/), [state-model](/design/state-model/).

## Qué se construyó

### `packages/editor` — el panel

Vite + React 19, sin librería de componentes y sin CSS-in-JS: variables CSS y
una hoja de estilos plana, como pide la sección 8 del diseño. `base: '/__laqi/'`
en la config de Vite, para que los assets no se pidan a la raíz y caigan en el
mock server del usuario.

La capa sin DOM va aparte y tiene sus propios tests:

| Archivo        | Qué resuelve                                                                 |
| -------------- | ---------------------------------------------------------------------------- |
| `types.ts`     | Las formas del control plane. `LaqiEvent` viene de `@laqi/core/events`       |
| `resolve.ts`   | Qué respuesta está viva y qué capa la decidió; la regla del click en el chip |
| `search.ts`    | El filtro de la lista y el matching multi-token de la paleta                 |
| `highlight.ts` | Tokenizer de JSON (~40 líneas, como pide el diseño) y el readout de validez  |
| `log.ts`       | Entradas del log, cap de 200, el texto `X-Laqi-Resolved` verbatim            |
| `api.ts`       | Cliente tipado; propaga el mensaje de error que ya redactó el servidor       |

Los componentes siguen el árbol del diseño: `Header`, `ErrorBand`,
`ScenarioStrip`, `EndpointList`/`EndpointRow`, `RequestLog`, `EndpointDetail`
(con `JsonEditor`), `CommandPalette`, `CreateEndpointRow`, `FreshProject`.

### Decisiones que el diseño no fijaba

- **El editor de JSON es un `<textarea>` transparente encima de un `<pre>`
  coloreado**, alineados carácter a carácter. El diseño pide explícitamente no
  traer un editor entero para esta superficie.
- **El tokenizer round-trippea cada carácter.** Lo que no reconoce sale como
  `plain`, así que un archivo a medio escribir se sigue pintando en vez de
  romper la vista. Hay un test que lo verifica sobre input malformado.
- **Nada de fuentes remotas.** Source Serif 4 y JetBrains Mono se piden por
  nombre y caen a las del sistema: el panel tiene que verse igual con el wifi
  apagado.
- **El `default` de un endpoint nunca puede quedar apuntando a una respuesta
  borrada.** Borrar la respuesta que era default reasigna el default a la
  primera que quede; si no, el archivo queda inválido y el endpoint deja de
  servirse.

### Dos huecos del contrato del Plan 2a que hubo que cerrar

El Plan 2a dejó el evento de request incompleto para lo que el diseño pide del
log. Ambos se arreglaron en `packages/server`, con tests:

1. **El handler de no-route no emitía evento.** El diseño hace de esa fila
   la más ruidosa del panel — «¿por qué mi mock no contesta?» es la confusión
   más común — y era literalmente inconstruible. Ahora emite, con
   `endpointId: null`.
2. **El evento llevaba `endpoint.path`, el patrón de la ruta.** Cien requests a
   `/users/1..100` se veían como cien filas idénticas. Ahora lleva el path
   pedido.

`resolvedName` y `resolvedLayer` pasaron a opcionales y están ausentes en un
evento no-route: no hubo nada que resolver. El panel branchea en
`endpointId === null`.

### `@laqi/core/events` como subpath

El panel necesita el tipo `LaqiEvent` pero corre en un navegador, y el barrel
`@laqi/core` re-exporta `loader` / `state-store` / `writer`, que importan
`node:fs`. El tipo estaba redeclarado en el editor, donde podía driftear del
real — y drifteó: `check-types` lo agarró en el primer build. El subpath
`@laqi/core/events` existe para eso.

Es el primer paso del problema del barrel que quedó anotado al cerrar el Plan
2a. `resolve.ts` es el otro candidato obvio a subpath cuando algo lo necesite.

### `apps/cli` sirve el panel

`createEditorApp()` se monta **antes** del control plane, porque el control
plane termina en un catch-all que se comería `/__laqi` y `/__laqi/assets/*`.
Va detrás del mismo gate de loopback: con `--host 0.0.0.0` no se monta ninguno
de los dos.

- La ruta de `dist/` se resuelve por el resolver de módulos, no relativa al
  archivo, así sigue andando cuando el CLI se empaquete (Plan 5).
- **El path traversal se rechaza explícitamente.** La guarda es load-bearing:
  se verificó sacándola, y Hono **no** normaliza los `..` de la URL —
  `/__laqi/assets/../../<archivo>` lee fuera de `dist/` sin ella.
- Sin build, responde 503 con la página que dice qué comando correr, en vez de
  un 404 mudo.

## Verificación

- **331 tests** en total (290 del repo + los del panel), `check-types` y `lint`
  limpios.
- 37 tests del panel corren el árbol React de verdad en jsdom.
- Round-trip completo contra un servidor real: las cuatro capas resuelven en el
  orden correcto (`default` → `state` → `scenario` → override gana al
  escenario → reset), y crear/editar/borrar escribe el archivo y se sirve al
  instante.
- El bundle no contiene `node:fs` ni `require(` — verificado sobre el build.
- El SSE entrega los cuatro eventos con los paths concretos y el no-route con
  `endpointId: null`.

## Fuera del alcance

- **La banda de sharing** (`Share publicly`, el túnel, el token) es del Plan 4.
  El header no dibuja el botón todavía: prometería algo que no existe.
- **`Open in editor`** (`$EDITOR file:line:col`) necesita que el CLI exponga
  una ruta para lanzarlo; sin plan asignado.
- **Autoría de escenarios** desde el panel — el
  [ADR-0008](/decisions/0008-multifile-and-names/) ya decidió que es a mano
  o vía MCP.
- **`1…9` para flipear en una fila enfocada** y el click derecho de la fila
  quedaron sin hacer; el resto del mapa de teclado (`⌘K`, `↵`, `⌘↵`, `esc`,
  `/`, `p`) sí está.
- **El panel no se empaqueta todavía** dentro del binario: hay que correr el
  build una vez. Eso es Plan 5.
