# laqi v2 — Plan 5: Documentation and packaging

**Status:** executed. Log of what was built.

## What it delivers

`npx laqi` working on plain Node, with the panel inside the package.

The documentation site (`apps/documentation`, Astro + Starlight) already
existed beforehand; this plan leaves it building alongside the rest and adds
the pages for plans 2b through 5.

## The bundle

`tsdown` packs `apps/cli` and every `@laqi/*` package into **a single
publishable package**. One is published, not six.

The panel travels inside as `dist/panel`: `packages/editor` is not published
separately, so without that `npx laqi` would serve the "not built" page
forever. **The build refuses to finish if the panel is missing**, instead of
silently producing a broken package.

`editorDistDir()` first looks for `dist/panel` next to the bundle and if that
fails resolves `@laqi/editor` via the module resolver — the same code serves
both the packaged build and the source tree.

## Two packaging bugs invisible until someone installs

1. **`catalog:` reached the published dependencies.** It is a bun/pnpm
   protocol; npm fails the whole install with `EUNSUPPORTEDPROTOCOL`.
   Versions are now pinned, and `package.test.ts` fails if any dependency
   uses a protocol npm cannot install, or if a pinned version drifts out of
   sync with the root catalog.
2. **The workspace packages were runtime dependencies.** Since they get
   bundled, npm would have looked for `@laqi/core` in the registry, where it
   does not exist. They are now devDependencies, and a test enforces it.

Also: `packages/editor` became `private` with no code entry point — its
`exports` pointed at a `src/dist-path.ts` that never existed.

## End-to-end verification on the real artifact

Not on the monorepo: on a tarball built with `npm pack`, installed with
`npm install` in an empty directory and run **with bun off the PATH**.

- `laqi --help`
- serving mocks with the correct `X-Laqi-Resolved`
- the panel and its assets, from inside the package
- the control plane, and full CRUD
- hot-reload on a hand-edited file
- the state and scenario layers
- the MCP server over stdio, with all nine tools

## The SSE leak that had been deferred

Plan 2a had noted that the CLI, run with `bun apps/cli/src/index.ts`, leaked
SSE listeners when the client disconnected — a limitation of Bun's engine,
not of the code.

Measured on the packaged binary under Node: **40 SSE clients opened and cut
plus 300 requests moved the server from 62 MB to 64 MB.** The published
artifact does not have the leak. The point is closed.

## Out of scope

- **Publishing to npm.** The package is ready; pressing the button is a
  decision for the repo's owner, not for this plan.
- **`{{uuid}}` templating** (defect E from the v1 analysis) still has no plan
  assigned.
- **Standalone binaries** (`bun build --compile`): the npm package covers the
  use case, and a per-platform binary is an entire release pipeline.
