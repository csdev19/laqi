# Generate hardening — design spec

**Status:** proposed, not implemented.
**Date:** 2026-10-12
**Ticket:** [NIW2-311 — Close SSRF, code injection and exponential blowups in @laqi/generate](https://linear.app/niway/issue/NIW2-311/close-ssrf-code-injection-and-exponential-blowups-in-laqigenerate) (parent audit NIW2-302)
**Amends:** [JSON Schema and adapters — design spec](/design/json-schema-adapters/) (three rows, listed under [Tension with existing documents](#tension-with-existing-documents))
**Creates:** ADR-0017 — References never leave the document, and there is no switch (`adr-no-external-refs.md`)

Normative statements use **must** / **must not**. Code blocks marked _illustrative_ show intent, not final declarations. Everything below was re-located in the read-only export of `origin/main`; file:line citations are to that snapshot. Reproductions marked _(reproduced)_ were run on 2026-10-12 against the working checkout, whose `packages/generate/src` differs from main only in `compile-schema.ts` (main additionally honours numeric `format`; the `$ref`, object and printer code is byte-identical). Nothing in this ticket is fixed on main.

## In one minute

`@laqi/generate` trusts its inputs in five places where it must not. A mock file in a cloned repository, an OpenAPI document someone shares, or a model pasted from a chat can today make the developer's machine issue HTTP requests and read local files (on export), put attacker-written lines into the TypeScript the panel offers to copy, block the single-threaded server for seconds with a 1.6 KB schema, multiply a spec's size by 200× on import, and read literal constants out of any `.ts` file reachable from the working directory. This spec closes all five without changing what laqi stores, what the Promise facades return, or the Effect boundary of [ADR-0012](/decisions/0012-effect-first-in-generate/).

### Open questions for the owner

1. **Prefix for digit-leading names.** `GET /2fa` → `T2fa` is proposed (common codegen convention). `_2fa` is the alternative; it reads as "private" to some people. Pick one; it is a one-line constant.
2. **`additionalProperties: <schema>` beside `properties`.** Proposed: compile the sub-schema (so a hidden `$ref` or an unsupported keyword inside it is refused) but keep generation unchanged and emit **no** diagnostic, because laqi never invents keys and the generated object satisfies the document. The audit (Q5) wanted a `loss.index-signature` warning; under the strict default that would start refusing OpenAPI imports that succeed today. Confirm "no diagnostic".
3. **Export of an already-stored snapshot with a non-local `$ref`.** Proposed: fail for every target, TypeScript included (today TypeScript prints `unknown` for it). The softer option is to keep TypeScript printing `unknown` and fail only quicktype targets. Proposed is the stricter one because the panel then shows one message instead of two behaviours.
4. **Audit Q7 (`MAX_SHAPE_DEPTH` counts two levels per `$ref` hop, so ~250 chained components refuse).** Not required by the acceptance criteria. Fold into D5 (count one level per hop) or leave for a later ticket?
5. **Seeded output for cyclic documents changes under D5** (see [Migration](#migration-and-breaking-changes)). Accept, or keep today's per-path re-expansion for documents that contain a cycle and rely on the node budget alone for them? Proposed: accept; the body is still a valid instance of the document, and the evidence's `bodyHash` protects an existing body from a silent overwrite.

### Out of scope

- `load-module.ts` (child env, output caps, verdict framing): NIW2-310.
- MCP tool annotations, `import_openapi`'s dropped responses, output caps on tool results: NIW2-314.
- Constraints on `SchemaSnapshot.name` or any `packages/schema` change: NIW2-315.
- The panel/TUI rendering of errors: NIW2-316.
- String-length and numeric-bound resource limits in generation (audit S8), `exclusiveMinimum` epsilon bug (Q4), pointer-unescape in `print-document.ts` (Q3), duplicated helpers (Q7). Worth doing; not what the ticket's acceptance asks for. Q3/Q4 appear in the partial patch and may ride along in the same PRs if the reviewer agrees, but this spec does not depend on them.
- Any sandbox for pasted code. There is none to build: pasted TypeScript is never executed, only type-checked.

## Threat model in one paragraph

The attacker controls one of: a mock file in a repository the developer clones (`laqi/*.json`, with a `schema` block), an OpenAPI or JSON Schema document the developer imports, or a TypeScript model pasted into the panel or sent by an agent to `generate_data`. They do not control the laqi process, the config, or the terminal. Their goals: make the developer's machine reach a URL or read a file (cloud metadata, internal admin, `~/.ssh`), get attacker text into code the developer copies into the project, or stop the mock server. Every surface in this ticket is reachable from those inputs without any confirmation step: export runs on a click in the panel or on `get_types` from an agent, import runs on `import_openapi` or the panel's create flow, and `parseTypes` runs on every paste.

## Findings

### F1 — SSRF and local file read on export (High)

**Current behaviour on main.**

- `packages/generate/src/print-types.ts:51` destructures `FetchingJSONSchemaStore` from quicktype-core and `:77` constructs it: `new JSONSchemaInput(new FetchingJSONSchemaStore())`. Every non-TypeScript export target goes through this (`export-types.ts:45-48`); TypeScript is printed by laqi itself (`export-types.ts:37-43`).
- quicktype-core 26.0.0's store (`dist/input/io/NodeIO.js`, `readableFromFileOrURL`) handles three address shapes: `file://` is turned into a path and read; anything `is-url` accepts is passed to `globalThis.fetch`; anything else is treated as a local path, symlinks resolved, and read with `fs.createReadStream` if it exists. There is no scheme or host check anywhere.
- `compile-schema.ts:641-647` refuses a `$ref` that does not start with `#` — but only for the schemas it walks. It never walks: `$defs`/`definitions`/`examples`/`default` (annotations, `:18-31`), or `additionalProperties` when `properties` is present (`:487` lists it as consumed, `:490-494` compiles only `properties`). _(reproduced)_: all three hiding places compile `ok: true`.
- A stored snapshot reaches export **without** the compiler: `apps/cli/src/serve.ts:428-440` only runs `SchemaSnapshotSchema.safeParse` (which checks `$schema` and shape, `packages/schema/src/schema-snapshot.ts:50-60`), and `serve.ts:245-262` / `packages/mcp/src/server.ts:323-333` export `response.schema` straight from the loaded mock file.
- _(reproduced)_: `exportTypes(snapshot, 'python')` with `additionalProperties: { $ref: 'http://127.0.0.1:<port>/latest/meta-data/' }` beside `properties` made **one GET** to the local server; `'typescript'` made none. A relative `$ref: 'other.json'` is looked up on disk relative to the process cwd (it failed only because the file did not exist). `$id` pointing at a URL did **not** trigger a fetch on its own.
- `print-types.ts:92` returns `String(e)` as the `PrintError` message, so quicktype's "Value of type … is not valid JSON Schema at <url>" echoes part of the fetched body to the panel or agent.

**Scenario.** A teammate's branch adds `laqi/users.json` with a `schema` whose `additionalProperties` references `http://169.254.169.254/latest/meta-data/iam/security-credentials/`. Anyone who opens the panel and clicks "Export → Python", or whose agent calls `get_types` with `lang: "go"`, has their machine issue that request, and part of the response comes back in the error text.

**Designed behaviour.**

- `printDocumentEffect` **must** construct `JSONSchemaInput` with a store whose `fetch()` returns `undefined` for every address. `FetchingJSONSchemaStore` **must not** be imported or constructed anywhere in `packages/`. A test asserts the symbol is absent from the package's compiled output.
- A new module `packages/generate/src/local-refs.ts` exports `findNonLocalRef(document): { pointer, ref } | undefined`. It **must** walk only schema positions — the same three keyword tables `normalize-dialect.ts:22-46` already uses (`SCHEMA_VALUED`, `SCHEMA_ARRAYS`, `SCHEMA_MAPS`, which include `$defs`, `definitions`, `properties`, `additionalProperties`, `items`, `prefixItems`, `allOf/anyOf/oneOf`, `not`, `if/then/else`, `patternProperties`, `dependentSchemas`, `propertyNames`, `contains`, `unevaluated*`) — plus the root. It **must not** descend into `examples`, `default`, `const`, `enum`, or unknown keywords. It **must** be iterative (explicit stack), so a document nested 100 000 levels deep cannot overflow the guard. It **must** treat `$ref`, `$dynamicRef` and `$recursiveRef` alike. A reference is local iff it is exactly `#` or starts with `#/`; `#anchor` forms are non-local for this purpose (laqi never supported anchors, and `compile-schema.ts:680` would mis-slice them — audit Q6).
- `compileSchema` **must** call `findNonLocalRef` on the whole document before compiling and refuse with `unsupported.keyword` at the offending pointer, using the existing message from `compile-schema.ts:644`. This closes the `$defs` and `additionalProperties` holes at import for every adapter (`import-schema.ts:206, 262, 355`).
- `object()` **must** compile `additionalProperties` when it is an object beside `properties`, discard the resulting plan, and keep generating exactly what it generates today (open question 2 for the diagnostic).
- `exportTypesEffect` **must** call `findNonLocalRef(snapshot.document)` first and fail with `PrintError` naming ref and pointer, for every target including TypeScript (open question 3). `printDocumentEffect` **must** repeat the check (it is public API and callable with any document).
- The `PrintError` message built from a quicktype failure **must** keep quicktype's text (it is the user's own document being described) — the body-echo concern disappears once nothing is fetched.

**Interfaces** _(illustrative)_:

```ts
// packages/generate/src/local-refs.ts

export const isLocalRef = (ref: string): boolean => ref === '#' || ref.startsWith('#/')
export function findNonLocalRef(document: unknown): NonLocalRef | undefined
export const nonLocalRefMessage = (found: NonLocalRef): string

// packages/generate/src/print-types.ts — inside printDocumentEffect, after the service yields

  async fetch(): Promise<undefined> { return undefined }
}
const input = new JSONSchemaInput(new LocalOnlyStore())
```

`JSONSchemaStore` is exported by quicktype-core 26.0.0 (`dist/input/JSONSchemaStore.d.ts`: `abstract fetch(address: string): Promise<JSONSchema | undefined>`). When `fetch` returns `undefined`, quicktype raises `SchemaFetchError: Could not fetch schema ${address}, referred to from ${base}` after one retry against an alternate base, with no I/O _(reproduced)_.

### F2 — Code injection and invalid identifiers in printed TypeScript (High)

**Current behaviour on main.**

- `print-document.ts:26-32` `uniqueName` only de-duplicates; `:38` and `:40` interpolate the result into `export interface ${name} {` / `export type ${name} = `; `:136-137` feed `typeName` (= `snapshot.name` from `export-types.ts:39`) straight in. `print-shape.ts:26-32, 43, 51, 74` do the same with `typeName` from `typeNameFor(id)` (`serve.ts:467-470`).
- `snapshot.name` is `z.string().min(1)` (`schema-snapshot.ts:52`); a `SourceRequest.name` is `z.string().min(1).optional()` (`packages/schema/src/source-request.ts:26,35`). Both are honest labels by the adapters spec and nothing constrains their characters.
- `fieldTypeName` (`print-shape.ts:93-99`) rebuilds property-derived names from `[A-Za-z0-9]` and upper-cases the first letter, so a property named `date` becomes the interface `Date`, `record` becomes `Record`, and `1st` becomes `1st`. `typeNameFor('GET /2fa')` returns `2fa` (`type-name.ts:2-12`).
- _(reproduced)_ with `name = 'X {}\nimport * as cp from "child_process"; cp.execSync("touch /tmp/pwn"); export interface Y'`: both printers emit a second line that is that import and call. _(reproduced)_: properties `date`, `record`, `when: date-time`, `map: Record<string,string>`, `1st` yield `export interface Date`, `export interface Record`, `when?: Date` now pointing at the user's `Date`, `map?: Record<string, string>` now a non-generic, and `export interface 1st {` which is a syntax error.
- Property keys and literal values are safe: `property()` (`print-shape.ts:114-116`) quotes anything that is not a bare identifier, `literals()` uses `JSON.stringify`. Nested interface names come from `fieldTypeName` and so are alphanumeric. The only raw interpolation is the root name — and the reserved/global collision affects every name.

**Scenario.** A mock file carries `"schema": { "name": "…" }` with the payload above. The panel's types view renders it, a developer (or an agent writing to `src/types/api.ts`) copies it, and the next `tsc`, test run or bundler evaluation with that file imported runs the attacker's import. The shadowing case needs no attacker: an ordinary API with a `date` object field produces types that compile against the wrong `Date`.

**Designed behaviour.**

- One function, `declarationName(raw: string): string` in `print-shape.ts`, is the only path to a name that follows `interface` or `type`:
  1. If `raw` matches `/^[A-Za-z_$][A-Za-z0-9_$]*$/` keep it; otherwise rebuild it with the same cleaning `fieldTypeName` applies (letters and digits only, camel-cased at the breaks). Non-ASCII letters are dropped, not transliterated; a result that is empty becomes `Type`.
  2. A leading digit gets the prefix from open question 1 (`T` proposed).
  3. The result is truncated to `MAX_NAME_LENGTH = 128` characters.
  4. If the result is in `RESERVED_NAMES` the suffix `Type` is appended (`Date` → `DateType`, `string` → `stringType`). `RESERVED_NAMES` **must** contain: every TypeScript reserved and strict-mode reserved word; the type keywords (`any`, `unknown`, `never`, `void`, `string`, `number`, `boolean`, `bigint`, `symbol`, `object`, `undefined`, `null`); the globals the printers themselves emit (`Date`, `Record`) and the built-in types a model commonly collides with (`Array`, `ReadonlyArray`, `Promise`, `PromiseLike`, `Map`, `Set`, `WeakMap`, `WeakSet`, `Object`, `String`, `Number`, `Boolean`, `Symbol`, `BigInt`, `Function`, `Error`, `RegExp`, `JSON`, `Math`, `ArrayBuffer`, `Iterable`, `Iterator`, `Generator`, `Partial`, `Required`, `Readonly`, `Pick`, `Omit`, `Exclude`, `Extract`, `NonNullable`, `ReturnType`, `InstanceType`, `Parameters`, `Awaited`). The list is a constant in code with a test that every entry is rejected; it is not meant to be exhaustive over `lib.d.ts`, only over what generated code and typical models touch.
- `declarationNamer()` returns a per-document function that applies `declarationName` and then uniques with a per-base counter (`Item`, `Item2`, `Item3`) so 1 000 siblings called `Item` stay linear (audit P5).
- `printDocumentTypeScript` and `printShapeTypeScript` **must** obtain every declared name — root, nested, `$defs`-derived — through that namer, and `printShapeTypeScript` **must** reserve the root name before typing the fields so a nested interface cannot take it (today a non-object root declares `export type ${typeName}` unsanitised, `print-shape.ts:74`).
- `typeNameFor` **must** return `declarationName(...)` of what it builds today (so `GET /2fa` → `T2fa`, `GET /` → `Response`).
- `exportTypesEffect` **must** pass `declarationName(snapshot.name)` as quicktype's `typeName` too. quicktype has its own per-language namers, so this is belt-and-braces; whether quicktype would emit a raw name is **unverified** and not relied upon.
- The stored `snapshot.name` is **not** modified, and no `packages/schema` constraint is added (D9). The panel keeps showing the label it stored; only code generation sanitises.

### F3 — Exponential `$ref` expansion in `compileSchema` (High)

**Current behaviour on main.**

- `compile-schema.ts:52-57` `Ctx` carries `following: string[]` and `depth`; `reference()` `:652` checks `ctx.following.includes(ref)` for cycles and `:668-672` compiles the target afresh on every use with a spread context. There is no memo and no node count; the only bound is `MAX_SHAPE_DEPTH = 500` (`shape.ts:27`, checked at `compile-schema.ts:112-114`).
- A document whose `$defs/Lᵢ` has three properties pointing at `Lᵢ₊₁` is compiled 3ⁱ times at level i. _(reproduced)_: 12 levels / 1 338 bytes = 129 ms, 13 levels = 349 ms, 14 levels / 1 578 bytes = 1 071 ms on an M-series laptop (the audit measured 13.7 s for 14 levels on its machine). Each level triples the time; 20 levels would not finish.
- The compilation is synchronous on the server's only thread and runs on import (`import-schema.ts:206, 262, 355`) and again on every `previewBody` (`:413`), including every `regenerate` and the `import_openapi` loop (`packages/mcp/src/openapi.ts:186-198`).

**Scenario.** An OpenAPI document with a chain of components each referencing the next a few times — a realistic shape for nested resource envelopes — is imported through the panel or `import_openapi`. The mock server stops answering every request for seconds to minutes. Nothing malicious is required; a hostile document simply makes it certain.

**Designed behaviour.**

- `Ctx` gains two fields shared by every copy of the context: `resolved: Map<string, Plan>` (by exact `$ref` string) and `work: { nodes: number }`.
- `reference()` **must** return `resolved.get(ref)` when present, before resolving the pointer. After compiling a target it **must** store the plan in `resolved` **unconditionally**, including targets that emitted `loss.circular` (cycle cuts) or `loss.unresolved-type` along the way. Rationale: a cut plan is a valid plan for that target; storing it keeps a diamond that contains a cycle linear instead of exponential. The diagnostics are pushed once, at the first encounter, with that encounter's pointer — this is what the existing tests in `compile-refs.test.ts:84-140` already assert, and both of them keep passing under unconditional memoisation (each `$defs` entry there is first compiled exactly once, in the context the test expects).
- A target refused with `RefusedError` is never stored (the whole compilation aborts anyway).
- `compile()` **must** increment `work.nodes` on every real node compilation (memo hits do not count) and refuse with `budget.exceeded` — error severity, not acknowledgeable, already in the table at `packages/schema/src/diagnostics.ts:117` — when `nodes > MAX_COMPILE_NODES` (`100_000`, exported, matching the `MAX_GENERATED_VALUES`/`MAX_INFERRED_VALUES` convention). Message: `this document expands to more than 100000 schema nodes once its references are followed`.
- `following` becomes a `Set<string>` copied per hop only when a hop happens (audit P4). Depth accounting is unchanged unless open question 4 is answered "fold in".
- `previewBody`'s second compilation (audit P2) is not removed here: with memoisation it is linear in document size and a plan cache keyed by document would be new state in the facades, which [ADR-0012](/decisions/0012-effect-first-in-generate/)'s runtime note warns against adding casually. Leave for phase-6 measurement.

### F4 — Exponential type expansion and real filesystem access in `parseTypes` (High + Medium)

**Current behaviour on main.**

- `parse-types.ts:102-111` builds `ts.createCompilerHost(options)` and overrides `readFile`/`fileExists`/`getSourceFile` only for the virtual file; everything else — `import './x'`, `typeof import('/abs/path')`, `/// <reference path>`, `node_modules/@types`, `package.json` lookups — goes to the real filesystem relative to `process.cwd()`. `options` (`:93-97`) do not set `noResolve` or `types`.
- _(reproduced)_: `export type X = { k: typeof import("<tmp>/secret.ts").KEY }` returns `{ kind: 'literals', values: ['sk-live-12345'] }` with **no** warning. The `/// <reference path>` variant did **not** leak in my run when the referenced file is a module (its `KEY` is not global); a script-style `.d.ts` with `declare const KEY` would, which is **unverified**.
- `toShape` (`:173-321`) has `MAX_DEPTH = 10` (`:26`), a `seen` set that is removed after each object (`:295, :310`), and no memo or visit count. _(reproduced)_: fan 4 / depth 9 = 79 ms, fan 5 / depth 10 (600 chars) = 699 ms, fan 6 / depth 10 (672 chars) = 2 602 ms; growth is fan^depth, so fan 8 / depth 10 is in the tens of seconds and fan 12 in the hours. Reachable from `generate_data`'s `model` (capped at 200 000 characters, which does not help) and the panel's paste.

**Scenario (read).** An agent, or a developer pasting a "model" from a blog or chat, includes `typeof import('../../.env.d')` or `import('/Users/me/project/src/config')`. Literal types — API keys written `as const`, feature flags, internal URLs — surface in the shape, then in the generated body, then in a committed mock file or in the agent's context.

**Scenario (DoS).** A 700-byte paste pins the server for seconds; a 2 KB one for hours.

**Designed behaviour.**

- Compiler options **must** add `noResolve: true` (TypeScript: "If `noResolve` is set, [adding resolved `import`/`<reference` files to the program] doesn't happen") and `types: []` ("If `types` is specified, only packages listed will be included in the global scope").
- The host **must** be built so that:
  - `readFile`/`fileExists`/`getSourceFile` serve the virtual file, and serve a real file only when its normalised path is directly inside `dirname(ts.getDefaultLibFilePath(options))` and its basename matches `/^lib\..*\.d\.ts$/`. Everything else is `undefined`/`false`.
  - `directoryExists` → `false`, `getDirectories` → `[]`, `realpath` → identity, `getCurrentDirectory` → `'/'`, `getCanonicalFileName` unchanged.
  - `resolveModuleNameLiterals` (TS ≥ 5.0) **must** return `{ resolvedModule: undefined }` for every literal, and `resolveTypeReferenceDirectiveReferences` likewise, so `import`, `import()` types and `/// <reference types>` all degrade to `any` → `loss.unresolved-type`, which is the documented contract (`parse-types.ts:46-49`).
  - `useCaseSensitiveFileNames` and `getNewLine` from the stock host are kept.
- `toShape` **must** become a memoising wrapper around the existing conversion: `converted: Map<ts.Type, Shape>`; a conversion that completed without a `loss.depth` cut is stored (cycle cuts are stored, as in D5); the wrapper increments `visits` and, past `MAX_TYPE_VISITS = 50_000`, throws a module-private `BudgetError`, which the program **must** turn into `ParseError` explicitly (a `catchIf`/`instanceof` branch placed before the existing `catchAllDefect` at `:341`), message `the model expands to more than 50000 nested types — simplify it or paste a smaller one`. The `ParseError` channel of `parseTypesEffect` is unchanged, which keeps the ADR-0012 invariant that error channels stay narrow.
- `MAX_DEPTH = 10` is unchanged.

### F5 — OpenAPI import embeds every component in every response (High, scalability)

**Current behaviour on main.**

- `openapi-extract.ts:85-87`: `componentSchemas(source)` plus `rewriteRefs(components)` for the whole bag, on every call; `:93-97` attaches all of it as `$defs`. The doc comment at `:49-53` states the rationale: reachability "is the compiler's job and its cycle handling".
- `packages/mcp/src/openapi.ts:186-198` calls `importSchema({ kind: 'openapi', document, pointer })` once per response, then `previewBody` compiles the full document again, then `normalizeDialect` walks it again for each.
- _(reproduced)_: 400 paths × 1 shared component + 400 unrelated components, 93.9 KB spec → 400 extractions totalling 18.4 MB (196×) in 75 ms. The audit measured 210 KB → 63 MB on its fixture. Every byte is then written to the mock files, loaded on every reload, and sent to the panel.

**Designed behaviour.**

- `extractResponseSchema` **must** attach, as `$defs`, exactly the components reachable from the rewritten response node by following `$ref` strings transitively: a worklist of component names, a visited set, names taken as the first pointer segment after `#/$defs/` (RFC 6901 unescaped), so `#/components/schemas/A/properties/x` pulls in `A`. Cycles terminate through the visited set. A `$ref` to a name that is not in `components.schemas` is left alone and keeps failing at compile time with `resolves to nothing`, as today.
- Rewriting **must** happen at most once per component per source document: a module-level `WeakMap<object, Map<string, { value, refs }>>` keyed by the `components.schemas` object. The `WeakMap` ties cache lifetime to the caller's document object; nothing is retained after the import loop drops it.
- `rewriteRefs` **must** build its copies with `Object.fromEntries` (audit S9: a JSON own key `__proto__` must stay an own key of the copy).
- `extractResponseSchema`'s existing contract — no `$schema`, OpenAPI-3.0-shaped output handed to `normalizeDialect({ assume: 'openapi-3.0' })`, `$defs` merged with any the node already carries — is unchanged. The doc comment at `:49-53` is rewritten to state the new rule and the measurement.

## Tension with existing documents

**[JSON Schema and adapters — design spec](/design/json-schema-adapters/).** Three rows change; this spec amends them in place when it lands.

1. _Additive support › Annotations_: "`$defs` … never affect generation, never rejected." Amended: `$defs`/`definitions` entries are schemas; a non-local `$ref` inside them is refused exactly as anywhere else. `examples`, `default`, `$comment`, `title`, `description` remain data and are never rejected.
2. _Additive support › References_: "any `$ref` outside the document → `unsupported.keyword`; never fetched." Unchanged in wording; now true for every schema position and for export, and backed by a store that cannot fetch.
3. _Budgets_: "Reference resolutions — 10 000 per import" is replaced by "Compiled schema nodes — `MAX_COMPILE_NODES` 100 000; converted TypeScript types — `MAX_TYPE_VISITS` 50 000". The spec marks these as starting values left to evidence; this is the evidence. Resolutions are no longer the unit of work once targets are memoised.

The spec's non-goals — "Remote `$ref` resolution. No network during import, generation or export" and "Deduplication and persistent caches wait for phase-6 measurements" — are respected: D1–D3 enforce the first; D7's `WeakMap` is a per-call working cache, not a persistent one, and D5/D6 add no cross-call state.

**[ADR-0012 — Effect-first inside `@laqi/generate`](/decisions/0012-effect-first-in-generate/).** No tension. Every change is internal to the package; the Promise facades keep their contracts; `parseTypesEffect`/`exportTypesEffect`/`printDocumentEffect` keep their exact error channels (`ParseError`, `PrintError`) and `R` requirements; the deny-all store is created inside the program that already yields the `Quicktype` service, so the lazy-load invariant (`lazy-deps.test.ts`) is untouched. One rule from the ADR's operational page is applied deliberately: the type budget surfaces as a declared `ParseError`, not as a defect caught by `catchAllDefect`.

**[ADR-0013](/decisions/0013-mocks-remember-their-model/)** (superseded): not affected; the stored form is unchanged.

**`openapi-extract.ts:49-53`'s in-code rationale** ("every component is carried … reachability is the compiler's job") is reversed by D7. It was written before the amplification was measured and before `import_openapi` stored one snapshot per response. The new comment states the measurement.

## Rollout

Each step is one PR, independently shippable, in this order:

1. **Stop the bleeding** — `local-refs.ts`, the deny-all store in `print-types.ts`, the export-time and compile-time walk, `object()` compiling `additionalProperties` beside `properties`. Tests: F1 table. Smallest diff, highest severity.
2. **Identifiers** — `declarationName`/`declarationNamer` in `print-shape.ts`, both printers, `typeNameFor`, quicktype `typeName`. Tests: F2 table, including the "every fixture is valid TypeScript" check.
3. **Compile budget** — memo + `MAX_COMPILE_NODES` in `compile-schema.ts`. Tests: F3 table, goldens re-run.
4. **Parse budget and isolation** — memo + `MAX_TYPE_VISITS`, the isolated host, in `parse-types.ts`. Tests: F4 table. Can be split in two if the host change needs its own review.
5. **Reachable `$defs`** — `openapi-extract.ts`. Tests: F5 table.
6. **Docs** — this spec into `design/`, the three amended rows in `json-schema-adapters.md`, the ADR into `decisions/`, a changelog note on the exported-name changes.

Each PR's verification: `bun run verify` (lint, format, build, type-check, the full suite) plus the new tests. vitest has no "deny network" switch, so step 1's proof is the counting local server plus a counting `readFile` spy, not an environment flag.
